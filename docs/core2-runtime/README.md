## What was implemented

`src/grade9qa/core2_render_hardening.py` is a small, **source-independent** patch utility. It does not commit the original Shared Python script, question stems, figures, answers, the existing full HTML, or licensed textbook material.

The utility accepts a trusted original `render_core.py` **read-only** and creates a separate candidate source file. It matches the original Shared code exactly, injects a CORE2-only JS customization, and changes only CORE2 role JS selection. Other Shared roles, including Core1B's separate boundary-commit JS, remain on the original JS.

- Before any Core2 answer reveal, verify successful first-response localStorage persistence AND readback (including exact saved input fields).
- Failed write, no available state key or bad readback keeps `data-attempted` unset and the solution locked; shows an explicit retry error.
- After successful first response, disable answer-input controls. Later help/hint state saves preserve the first committed answer fields; reload restores attempted state with inputs disabled.
- Remove the author-only `g9MaterialiseAll()` reveal hook from CORE2 learner role pages.

This mitigates a real bug where original `saveCore2State()` was called **after** unlocking and materializing the answer.
