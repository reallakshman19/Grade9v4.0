How to build a trustworthy learning journey

This is the operational explanation—not merely an index. Concept note · 01

Separate the learner's journey from the evidence that qualifies it

The learner follows a simple loop: original question → understand the idea → independently solve a different problem → return to the original question. The author follows an evidence process that asks whether the source is real, the physics is valid, the exact reasoning has been identified, and the teaching can prepare a genuinely independent attempt. These are related workflows, not one interchangeable chain of approvals.

What the child sees

Learn → Challenge is a gateway, not a fourth Core. It selects a question or concept and connects Core2 (original question), Core1A (teaching the reasoning) and Core1B (fresh reasoning practice). The same lesson page may contain both Core1A and Core1B.

Foundation lessons, C01–C08, E01–E05 and F01–F03 are different collections of current WPE practice. Their page names are not QRT academic qualifications.

What the agent must prove

Can the child identify a model and its conditions? Does the guided example truly teach the decisive operation? Does the fresh task demand a new inference that has not been given away? Are the original question and the learner's first response preserved?

Source correctness, scientific correctness, independent cognitive review, learner evidence and release permission are separate gates. A green browser test does not collapse them.

The system uses the seven candidate cognitive-operation labels RETRIEVE, EXPLAIN, APPLY, MODEL, REPRESENT, SYNTHESIZE and JUSTIFY. They describe the decisive act of an exact task, not a topic-wide label, the length of a solution or a chapter badge. The five task-demand factors are model selection, representation translation, reasoning chain, computational load and exception sensitivity. An author may record a proposal; an independent reviewer must judge the exact original where authorized.

The Physics D3/D4 Blueprint and WPE adapter are draft candidates; an unselected adapter, disputed QRT operation, missing figure, or source-key conflict is not repaired by a good-looking learning page. Use NOT_RUN, HOLD or SPEC_PENDING when that is the evidence.

Concept note · 02

Two evidence routes meet at the construction requirement

A new agent must not construct a lesson by reading only a question stem and its answer. There are two distinct evidence routes:

Route A — exact question and assessment demand

  1. Identify the exact examination or textbook question, source category, edition/session, options, diagrams and key provenance.
  2. Retain native SL1 custody and optional real P1 first-attempt evidence.
  3. Read SL2 as a proposed cognitive operation and intrinsic-demand explanation, not a verdict.
  4. Obtain separately authorized, source-only QRT review when required; determine the shortest valid inference and the distinct role of the source.
  5. Define the precise learner-owned move the eventual fresh task must test.

Route B — source exposition and disciplinary truth

  1. Locate a relevant textbook/syllabus passage, scientific law, graph or representation, with its source and rights.
  2. Record claims, conditions, units, direction of inference, exceptions and plausible wrong models.
  3. Check those warrants with appropriate subject expertise rather than relying on a coaching answer.
  4. Identify the prerequisites and a different guided example that can teach the reasoning.
  5. State what is unknown or disputed rather than silently filling gaps from an authored explanation.

Join point: A proposed or reviewed task demand must match a suitably grounded scientific teaching obligation. The construction binder links the exact task to the precise concept, conditions, representations and independent reconstruction. A matching ID, broad topic or syllabus term alone does not establish this join. The native/Owner-specific sequence and authoring gates still apply; preparation can precede formal acceptance without claiming it.

Distinguish source roles. An authenticated original exam question, a textbook prerequisite and an authored transfer challenge can all help learning, but only the authenticated original can serve its own direct-exam evidence role. Never rename an authored task as an examination question to fill a coverage gap.

Agent guidebook · 04

Repeatable one-question-to-one-construction procedure

Execute these steps for one exact source ID before scaling to a batch. The output of each step is inspectable; do not substitute a status badge for evidence.

  1. S0 — Pin the task. Record repository head, question ID, requested deliverable, role/authority and test boundary. Do not re-open merged work or take over another agent's lane.
  2. S1 — Verify source identity. Read original stem, choices, diagram and source-key custody. Keep an authored sketch separate from a verified exam figure. Distinguish official answer from coaching prediction.
  3. S2 — Record the intellectual demand. Find the shortest correct model and decisive step. Compare candidate operations and five demand factors; preserve author SL2 proposals as proposals. Never infer demand solely from formula complexity.
  4. S3 — Respect independent QRT. A separately appointed first-pass reviewer receives only the authorized source-only materials. Authors and engineers report a provisional route or NOT_RUN, never manufacture a review receipt or sign their own work as independent.
  5. S4 — Inspect Blueprint and topic adapter. For Physics/WPE, use the current pinned subject-specific Blueprint and selected adapter if approved; otherwise retain draft and UNSELECTED status. Do not force a D2 source into a D3 tile because D1/D2 guidance is pending.
  6. S5 — Derive a construction requirement. Write the exact skill to teach, prerequisites, model assumptions, scientific warrant, source-task linkage and protected new inference W. Compare with existing C/E/F lessons to prevent duplicate content.
  7. S6 — Build complete Core1A. Conventions → before-you-start prerequisites → model construction with reasons → fully worked different anchor → tempting wrong path → independent exit check. Diagrams must match the physical phase and be accessible.
  8. S7 — Build Core1B. Create a fresh MAIN/instance task whose crucial inference is not already answered in Core1A. Predict → Attempt → Reconstruct → Diagnose → Repair → Boundary test. Help is optional and its exposure recorded honestly.
  9. S8 — Connect the student loop. Use the verified Question Bank ID and direct lesson URL; preserve the learner's previous attempt, return to that exact ID and avoid iframe embedding. Distinguish related practice from sufficiently matched teaching.
  10. S9 — Verify and deliver. Recalculate equations and boundary cases, test full browser journeys, check B1–B7, compare source blobs, report all holds and create a scoped PR with exact-head CI. No academic approval inferred from software validation.

For batch work, repeat S1–S9 for every ID, including unmapped IDs with a named reason. Never treat all questions in a topic as the same cognitive operation. Version/hash changes invalidate earlier checks unless re-verified.

Teaching / transfer contract · 05

What sufficient Core1A and protected Core1B actually mean

Core1A is the explanation the child needs to construct a model herself. It must establish the law, conventions, assumptions, action-and-reason chain, model selection, limits, and an explicit plausible error. A memorised worked answer without a reason is not sufficient teaching.

Core1B is not a second copy of Core1A. Define Y as the taught skill, Z as the connecting route and W as the inference the learner must make without being told. Work through Y and show Z enough to support the attempt, but do not reveal W in the guide, hints, alt text or pre-attempt labels.

Core1B stageWhat the child doesEvidence / reveal rule
1 · PredictPredict the physical result and say whyCapture the first model, even “I'm not sure”
2 · AttemptChoose a model and submit an independent calculation or argumentSave the initial response separately from later edits and record help exposure
3 · ReconstructCompare the attempt with a warranted worked reconstructionReveal the full model after commitment; never silently rewrite the first answer
4 · DiagnoseIdentify the first mistaken assumption or inferenceFeedback should use actual response evidence, not just a generic error menu
5 · RepairExplain a revised decision and why it worksStore a distinct repaired model, not an overwrite
6 · Boundary testTry a changed condition or limiting caseGet a fresh attempt before showing that condition's worked check

Hints have three progressively more helpful purposes: H1 clarify the relevant givens; H2 connect to the previously taught law; H3 open a route without supplying W. If help was opened before the first attempt, call that response helped, not unassisted. Browser local storage is not a secure assessment record or proof of identity.

Construction binder: B1–B7 witnesses

WitnessConcrete question the author / reviewer must answer
B1 · TargetWhat exact source task and decisive operation is this construction intended to support?
B2 · SignatureDo the taught and fresh problems demand the same kind of reasoning, rather than share a topic name?
B3 · Teaching sufficiencyAre prerequisites, conditions, full worked reasoning, wrong path and exit check actually taught?
B4 · Fresh reconstructionWhat inference W must the learner own that cannot be copied from the guided example?

Six panels are necessary UI structure, not sufficient B1–B7 evidence. A progress counter reports completed practice stages, not demonstrated mastery. Only authorized reviews and actual learner evidence can support stronger claims.

Worked WPE construction · 06

An actual question-to-lesson decision and a fresh Physics calculation

Example A — EX-M79 → C03 → EX-M79

Exact source: EX-M79. Available related practice: C03, “Energy added each second.” Its guide teaches a constant-power case; the original source has a speed–distance relationship. That means C03 is related reasoning practice, not proof that EX-M79 itself has constant power. The child can learn the power/energy relationship and still must choose the original question's model independently on return.

Core1A: Teach the distinction among work, kinetic-energy change, instantaneous power and the independent variable of a graph. Core1B: Give a different speed/energy setting and protect the model choice before revealing the solution. Core2 return: use the same EX-M79 source ID; do not infer approval or overwrite its first response.

Example B — a verified worked teaching anchor for applied versus net power

An ideal 2 kg carriage is pulled upward by a 30 N cable over 1 m, from rest, with g = 10 m/s². Weight is 20 N downward and net force is 10 N upward. Net work is 10 J, so ½mv² = 10 J and v = √10 m/s at release.

Just before release, cable power is 30 × √10 ≈ 94.9 W. The net rate of translational kinetic-energy gain is 10 × √10 ≈ 31.6 W. Their difference is the gravitational potential-energy increase rate. After detachment the cable does no further work.

Protected new decision W: In a separate launch problem, decide which force's power is requested and where contact ends, before calculating. An optional second transfer challenge may later reuse PR #55's different toy/cable scenario inside F01–F03; it is planned, not merged, and must not duplicate an entire lesson engine.

EX-M97 warning: For a real person jumping, ground contact can be stationary. Ground-force × centre-of-mass speed is then a centre-of-mass pseudo-work rate, not automatically measured internal muscular power. Do not “correct” the original examination key solely by substituting 9.39 kW for a 6.26 kW coaching calculation; preserve the source conflict for review.

Examples are authored instructional illustrations, not authenticated examination questions or independent academic admissions.

QA, honesty and safety · 07

What to test; what PASS, HOLD, FAIL and NOT_RUN mean

CheckWhat the evidence can establishIt cannot establish
Source/identity pinsCorrect stable IDs, bytes, files and explicit original/synthetic rolesOfficial key authenticity without independent custody
Physics calculationNumerical values, units, signs, laws, assumptions and limiting cases in the checked modelCorrectness of a different unstated physical model
Python and schema testsNamed invariants for the exact version and inputs testedIndependent QRT, source validity or child comprehension
Real Chromium desktop/mobileActual navigation, stage order, response preservation, optional hints, refresh, reset and returnSecure testing or long-term learning transfer
B1–B7 evidence reviewWhether planned and observed construction witnesses exist and are coherentAutomatic academic admission from a checklist

PASS means a named, run check passed at its pinned version. HOLD means required evidence or authority is absent. FAIL means an actual contradiction or invalid claim was established. NOT_RUN is not a failed test and not an implied PASS. Never create reviewer approvals, backdate learner evidence or auto-join conflicting versions.

Student-flow security: Do not use iframes for WPE student learning integration. Directly link the verified destination, keep the source question ID intact and preserve attempted answers across page changes. Current study-bridge.html still contains an iframe and is a planned integration correction; the Architecture page documents this gap, it does not claim the code has already been repaired.

Agent output contract · 08

What a new agent returns at its checkpoint

A new implementing agent should finish its assigned PR—not hand off a pending task—before proposing a different assignment. Record the exact GitHub branch/head, changed files, source IDs, existing lesson reuse and the evidence for every numbered claim.

Required return

  1. Scope: subject, exact question(s), role, current branch/head and permissible file boundaries.
  2. Reasoning: decisive cognitive move, assumptions, source/figure/key state and proposed versus reviewed status.
  3. Construction: what Core1A teaches, what fresh W remains for Core1B, worked values and boundary tests.
  4. Integration: exact source-to-lesson-to-source links, local attempt preservation, clear related-vs-sufficient labels and no iframe.
  5. Verification: Python output, browser viewport routes, numerical negative controls, B1–B7 evidence and every NOT_RUN/HOLD.
  6. Delivery: PR URL, exact head, green CI scope, release/academic decision still outstanding and the next bounded action.
